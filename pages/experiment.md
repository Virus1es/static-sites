## Назначение

В рамках демонстрационного эксперимента рассматривается сравнение
нескольких стратегий управления кэшем.

На текущем этапе используются синтетические данные, созданные
специально для демонстрации воспроизводимого конвейера. Они не являются
результатами реального экспериментального исследования.

Основная задача демонстрации заключается в автоматизации
последовательности:

исходные данные → расчёт показателей → визуализация → публикация.

## Исследуемые методы

В демонстрационном наборе представлены пять методов.

### LRU

**LRU (Least Recently Used)** — стратегия удаления объекта,
ориентированная на давность его последнего обращения.

При необходимости освободить место в кэше удаляется объект,
к которому дольше всего не обращались.

### LFU

**LFU (Least Frequently Used)** — стратегия, использующая частоту
обращений к объектам.

При переполнении кэша удаляется объект с наименьшим количеством
обращений.

### Adaptive

**Adaptive** — демонстрационная адаптивная стратегия, учитывающая
изменение характеристик обращений к данным.

В рамках текущего набора данных метод представлен как отдельная
стратегия для сравнения с классическими политиками кэширования.

### Predictive

**Predictive** — демонстрационная прогнозирующая стратегия,
использующая информацию о предполагаемых будущих обращениях
к данным.

В дальнейшем этот вариант может быть заменён реальной моделью
предсказательного кэширования из экспериментального стенда.

### Cache Miss Prediction

**Cache Miss Prediction** — демонстрационный метод прогнозирования
вероятности промаха кэша.

Его назначение состоит в предварительном выявлении обращений,
которые с высокой вероятностью не будут обслужены из кэша.

В дальнейшем метод может быть реализован на основе реальной модели
машинного обучения.

## Сценарий эксперимента

Для каждого метода используется несколько условных запусков
в одном сценарии — распределённой среде.

Каждая запись содержит значения трёх основных показателей:

- доли попаданий в кэш;
- доли промахов;
- времени ответа.

Использование нескольких запусков позволяет рассчитывать средние
значения показателей и оценивать разброс времени ответа.

В текущей демонстрационной версии используется по три запуска
для каждого метода.

## Исходные данные

Основным источником данных является файл:

`data/experiment_results.csv`

Каждая строка содержит следующие поля:

`run` — номер запуска;

`method` — исследуемый метод;

`scenario` — сценарий эксперимента;

`hit_rate` — доля попаданий в кэш, %;

`latency_ms` — время ответа, мс;

`miss_rate` — доля промахов кэша, %.

Пример структуры записи:

`run,method,scenario,hit_rate,latency_ms,miss_rate`

## Обработка данных

Обработка выполняется скриптом:

`scripts/analyze.py`

Скрипт выполняет следующие операции:

1. загружает исходный CSV-файл;
2. проверяет наличие обязательных столбцов;
3. проверяет корректность типов данных;
4. группирует записи по исследуемому методу;
5. рассчитывает агрегированные показатели;
6. формирует статические и интерактивные графики;
7. создаёт таблицу результатов;
8. формирует страницу результатов для Nikola.

Полученные материалы сохраняются в каталоге `generated/`
и используются при последующей сборке сайта.

## Кэширование результатов

Для предотвращения повторного выполнения неизменившихся расчётов
используется контрольная сумма исходных данных и кода анализа.

При совпадении контрольной суммы предыдущий результат считается
актуальным, поэтому повторный расчёт пропускается.

Схема работы:

данные и код анализа → вычисление fingerprint → проверка кэша.

При отсутствии соответствующего результата выполняется полный
пересчёт.

При изменении исходного CSV или кода анализа fingerprint изменяется,
и результаты формируются заново.

## Сборка сайта

Весь процесс объединён с помощью Nox.

Обычная сборка с использованием кэша выполняется командой:

`python -m nox -s build`

Принудительный пересчёт результатов выполняется командой:

`python -m nox -s build_force`

В результате последовательно выполняются анализ исходных данных
и сборка статического сайта средствами Nikola.

## Результат эксперимента

Рассчитанные показатели и визуализация представлены на странице
«Результаты».

На текущем этапе страница использует синтетический набор данных.
При появлении результатов реального экспериментального стенда
исходный CSV может быть заменён без изменения общей архитектуры
pipeline.

Таким образом, текущая реализация служит прототипом воспроизводимого
процесса публикации результатов будущих экспериментов по кэшированию.
